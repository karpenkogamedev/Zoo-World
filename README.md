# Zoo World

### Zoo World — Тестовое задание

#### Описание

Zoo World — это 3D-игра, в которой можно видеть разных животных.

#### Камера

Вид сверху (`top down view`).

#### Графика

Графика не требуется. Можно использовать кубы, сферы и любые другие простые примитивы.

Разрешается использовать любые ассеты из asset store или других источников, но это никак не влияет на итоговую оценку.

#### Геймплей

Каждые `1–2` секунды появляется одно животное и начинает двигаться случайным образом. Животные могут сталкиваться друг с другом с использованием физики.

Если животное выходит за пределы экрана, оно должно менять направление движения и возвращаться обратно в видимую область.

#### Пищевая цепочка

##### Жертвы

Если жертва сталкивается с другой жертвой, они просто разлетаются в стороны под действием физики.

Если жертва сталкивается с хищником, она погибает и исчезает с экрана.

##### Хищники

Если хищник сталкивается с любым другим животным, жертвой или хищником, он съедает его.

Если хищник сталкивается с другим хищником, один из них должен выжить, а второй погибнуть. Можно выбрать любой самый простой способ реализации.

Каждый раз, когда хищник съедает другое животное, под хищником должна появляться надпись `Tasty!`.

#### Животные

##### Frog

Лягушка — это жертва.

Её тип движения — прыжки. Каждые `x` секунд она должна совершать прыжок на фиксированное расстояние.

##### Snake

Змея — это хищник.

Она движется линейно, с фиксированной скоростью в единицу времени.

#### UI

В правом верхнем углу должен быть счётчик погибших животных: и жертв, и хищников.

Интерфейс должен быть сделан на `uGUI`.

#### Что важно в этом тестовом задании

Самое важное, на что смотрят в этом задании — архитектура животных.

Код должен быть:

- понятным;
- легко расширяемым;
- легко читаемым.

Нужно исходить из того, что в будущем в проект будет добавлено `1000` разных животных: птицы, пауки, рыбы, крабы и так далее.

Также будет плюсом, если в проекте используются DI-фреймворки или другие архитектурные инструменты.

Если есть опыт работы с архитектурными паттернами, это тоже стоит показать в решении.

Проект нужно опубликовать в git-репозитории и отправить ссылку.

`ECS` использовать не нужно.

## Что использовал

- `Zenject` — для DI и разбиения зависимостей по установщикам.
- `UniTask` — для асинхронного показа и анимации `Tasty!`-лейблов.
- `UniRx` — для реактивных счётчиков статистики и UI-подписок.
- `uGUI` + `TextMeshPro` — для HUD и всплывающих текстов.
- `ScriptableObject` — для конфигов животных, UI и игровых правил.
- Встроенный `Unity Physics` — для столкновений животных.
- Пулы объектов — для переиспользования животных и UI-лейблов.

## Как это устроено в проекте

Проект разделён на несколько независимых зон ответственности.

`Configs` хранит данные в `ScriptableObject`: параметры спавна, лимиты, конфиги лягушки и змеи, UI-настройки и параметры пищевой цепочки.

`Infrastructure/Installers` собирает зависимости через `Zenject`. Конфиги, сервисы спавна, фабрики животных, статистика, UI и правила столкновений регистрируются отдельно, поэтому игровую логику можно расширять без жёстких связей между системами.

`Animals` содержит код самих существ: представление, runtime-контроллер, state machine, фабрики и стратегии движения. Сейчас в проекте есть два типа движения:

- `JumpMovementStrategy` для лягушки.
- `LinearMovementStrategy` для змеи.

`Infrastructure/Services` реализует прикладные правила игры:

- перенаправление движения обратно на экран;
- выбор результата столкновения;
- убийство и удаление животных;
- поддержание пула животных;
- учёт активной популяции;
- обновление статистики смертей.

`Gameplay/Statistics` и `UI` отвечают за интерфейс. Счётчики смертей публикуются как реактивные значения через `UniRx`, а HUD подписывается на них и обновляет текст в `uGUI`. Надпись `Tasty!` создаётся через отдельный поток запросов и показывается из пула UI-элементов.

## Что уже реализовано

- Животные появляются с интервалом от 1 до 2 секунд.
- Спавн идёт в пределах игровой платформы.
- Лягушка является жертвой и двигается прыжками.
- Змея является хищником и двигается линейно.
- Животные сталкиваются через физику Unity.
- При выходе за пределы видимой области движение перенаправляется обратно в игровую зону.
- Жертва погибает при столкновении с хищником.
- При столкновении хищника с другим хищником выживает один, второй погибает.
- После поедания над хищником показывается `Tasty!`.
- В правом верхнем углу UI отображаются счётчики погибших жертв и хищников.
- Для животных и `Tasty!` используется переиспользование объектов через пул.

## Как добавить новое животное

Базовый сценарий расширения уже подготовлен под данные и стратегии:

1. Создать новый `AnimalData` в `Assets/Data/Animals/`.
2. Назначить роль: `Prey` или `Predator`.
3. Назначить prefab `AnimalView`, материал, scale и collision impulse.
4. Выбрать тип движения и соответствующий `AnimalMovementConfig`.
5. Добавить новый asset в список `_animalCatalog` у `ConfigInstaller`.

Если нужен новый способ движения, достаточно добавить новый `AnimalMovementConfig`, стратегию движения и builder, после чего зарегистрировать его в `MovementFactory`.

## Как запустить

1. Открыть сцену `Assets/Scenes/SampleScene.unity`.
2. Проверить, что на сцене настроены installer-компоненты:
   `ConfigInstaller`, `AnimalInstaller`, `SpawnInstaller`, `GameplayInstaller`, `UIInstaller`.
3. Убедиться, что в `ConfigInstaller` назначены:
   `GameRuleConfig`, `TastyLabelConfig`, `UIDisplayConfig` и список животных.
4. Нажать `Play`.

Дополнительной сборки ассетов или внешней загрузки данных проект не требует.
